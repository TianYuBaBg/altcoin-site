Altcoin 公告知识库 — 项目需求文档 ​

版本 1.0 | 2026-06-07

1. 项目概述 ​

1.1 项目定位 ​

Altcoin 公告知识库是一个自动化的山寨币项目数据采集、整理与展示系统。核心任务是从 Bitcointalk 论坛的 Altcoin Announcements (ANN) 板块持续发现新项目公告，提取结构化信息，生成中文知识库，并通过静态网站对外展示。

1.2 目标用户 ​

  • 加密货币投资者和研究者，寻找早期山寨币项目
  • 对 PoW 挖矿币种感兴趣的矿工群体
  • 区块链历史研究者，关注项目生命周期

1.3 核心指标 ​

指标当前值
收录项目数~440 个
覆盖交易所SafeTrade、Nonkyc
上币研究页~28 个
部署周期每 4 小时自动构建

2.2 核心数据流 ​

Bitcointalk ANN 板块 (board=159/240/160)
    ↓ 扫描 → 过滤 → 提取候选
候选列表 JSON (new_candidates_*.json)
    ↓ 抓取帖子 HTML → 解析详情
详情缓存 JSON (batch_details.json)
    ↓ 解析 ticker/名称 → 生成 Markdown
项目文件 docs/projects/中文名_TICKER_英文名.md
    ↓ VitePress 构建时数据加载
    ↓ 评分 / 标签检测 / 交叉引用
静态 HTML → GitHub Pages

TianYuBaBg/altcoin-site公开GitHub Pages 托管仓库，仅包含构建后的静态文件

3. 数据采集功能 ​

3.1 板块扫描 ​

系统支持从三个 Bitcointalk 板块扫描新项目：

板块 ID名称扫描脚本过滤规则
159Altcoin Announcements (主板块)auto_scan.pyANN 模式匹配 + 标题关键词过滤
240Tokens (子板块)scan_board_240.py标签匹配 [ANN] + 关键词过滤
160Mining (挖矿板块)scan_board_mining.pyPoW/挖矿相关匹配 + 矿池/矿机过滤

扫描过滤规则：

  • 必须匹配 ANN 公告模式（如 (TICKER)、[ANN]、Announcement 等）
  • 跳过政治、工具、赏金、空投、买卖、诈骗等无关帖子
  • 最低标题长度 12 字符
  • 跳过已收录项目（基于 topic_id 去重）
  • 主题 ID 需 >= 5570000（约 2025 年以后）

ANN 公告模式（正则匹配，满足任一即可）：

  • (TICKER) 或 [TICKER] 格式的 2-8 位大写字母数字组合
  • 关键词：ANN、ANNOUNCEMENT、mine、blockchain、mainnet、testnet
  • 算法名：SHA-256、Scrypt、RandomX、Ethash
  • 共识机制：proof of work、proof of stake
  • 基础设施：L1、L2、protocol、network、platform

3.2 候选管理 ​

候选文件格式：

json
[
  {"tid": 5584473, "title": "[ANN] ZENOX TOKEN ($ZNX) | Polygon Network", "score": 1}
]

详情抓取 (fetch_candidates.py)：

  • 从 Bitcointalk 帖子 HTML 提取：发帖人、创建日期、最后活动日期、帖子内容摘要（最多 500 字符）、外链（最多 15 条）
  • 过滤模板域名（bitcointalk.org、mysql.com、php.net 等）
  • 支持 --tid N 单条处理（新增）
  • 结果追加到 batch_details.json，自动去重

3.3 项目文件生成 (gen_candidates.py) ​

文件名规则： {中文名}_{TICKER}_{英文名}.md

  • 三段式，下划线分隔
  • TICKER 仅含 ASCII 字母数字，最多 8 字符
  • 中文名由翻译脚本补全，初始为空

ticker 提取优先级：

  1. (TICKER) 格式（排除已知虚假 ticker：ANN、UPDATE、TESTNET、FREE 等）
  2. [TICKER] 格式
  3. | TICKER | 格式

英文名称提取：

  • 去除 [ANN]、UPDATE、TESTNET 等前缀
  • 去除方括号内容、管道分隔符、HTML 实体
  • 截取最多 60 字符

状态推断规则：

条件状态
标题含 mainnet/launched/live on主网已上线
标题含 testnet/test net测试阶段
标题含 pre-sale/presale预售阶段
最后活动 ≤ 90 天 且 回复 ≥ 5活跃中
最后活动 ≤ 90 天新项目
最后活动 ≤ 365 天待确认
其他已归档

3.4 中文名称补全 (batch_translate.py) ​

  • 读取 data/to_translate.json 清单
  • 按清单逐个修改项目文件的 H1 标题，添加中文名
  • 未匹配项需人工修正

3.5 回复/浏览统计 (fetch_stats_v2.py) ​

  • 并行扫描三个板块（5 线程 ThreadPoolExecutor）
  • 从板块列表页的 HTML 表格中提取回复数和浏览数
  • 范围：offset 0 到 42000，步长 40（~1050 页/板块）
  • 只保存已收录项目的统计数据
  • 输出：data/topic_stats.json（增量更新）

4. 数据刷新功能 ​

4.1 交易所行情 (fetch_exchange.py) ​

数据源：

  • SafeTrade: api.safetrade.com/v2/trade/public/markets + /tickers
  • Nonkyc: api.nonkyc.io/api/v2/markets + /tickers

处理逻辑：

  • SafeTrade：只取 state == "enabled" 的交易对，按创建时间降序
  • Nonkyc：只取活跃的现货交易对，按 MongoDB ObjectId 中的时间戳排序
  • 合并到 coins.json，按创建时间全局排序
  • 支持 --ticker TICKER 单币种刷新（新增）

输出： docs/public/coins.json

json
{
  "coins": [
    {"exchange": "SafeTrade", "name": "PRL/USDT", "base": "prl",
     "last": "0.79", "change": "+3.95%", "volume": "12345"}
  ],
  "updated": "2026-06-07 12:34:56"
}

4.2 GitHub 数据 (fetch_github.py) ​

  • 扫描所有 .md 项目文件，提取 github.com/owner/repo 链接
  • 调用 GitHub REST API /repos/{owner}/{repo} 获取：star 数、fork 数、issue 数、最后推送时间、是否归档、描述、语言、标签
  • 速率限制处理：403/429 时自动等待 60 秒重试一次
  • 增量更新：保留已有数据，只获取新仓库
  • 支持 --ticker TICKER 单项目刷新（新增）

输出： docs/public/github_data.json

4.3 上币公告 (fetch_listings.py) ​

数据源：

  • SafeTrade：Zendesk Help Center API（纯 HTTP）
  • Nonkyc：Playwright 渲染 SPA 分页 + HTTP 获取文章详情

提取信息： ticker、项目名称、官网上币公告链接、交易对链接、上币日期

输出： docs/public/exchange_listings.json

json
{
  "safetrade": [{"ticker": "PRL", "name": "Pearl", "listing_date": "2025-07-31", ...}],
  "nonkyc": [...],
  "_meta": {"generated_at": "2026-06-07T...", "safetrade_count": 50, "nonkyc_count": 30}
}

4.4 上币研究报告生成 (generate_research_pages.py) ​

生成条件（三重过滤）：

  1. 项目 ticker 必须存在于 coins.json（已在交易所上市）
  2. 项目 ticker 必须在 exchange_verified.json 中标记为 confirmed 或 likely
  3. 项目创建日期必须为 2026 年（当前研究范围）

幂等性：

  • 已存在的文件保留不覆盖（保护手动编辑）
  • 自动检测手动编辑信号（/last30days、## 关键信号、## 风险提示 等），有这些标记的文件不会删除

输出： docs/exchange-research/{TICKER}.md（Vue 驱动的 Markdown 组件页）

10.1 性能 ​

指标目标

10.2 健壮性 ​

  • 所有 HTTP 请求有超时（15-30 秒）
  • 错误数据优雅降级（不阻断流水线）
  • 扫描失败不阻断部署（continue-on-error: true）
  • 幂等操作：重复执行不产生重复数据
  • API 降级链：Binance → CoinGecko → 硬编码数据

10.3 安全 ​

  • 源码仓库私有，仅公开构建后的静态站点
  • GitHub Token 用于数据获取（更高 API 速率限制）
  • 部署密钥用于跨仓库推送（ACTIONS_DEPLOY_KEY）
  • 不存储用户凭证或隐私数据

10.4 编码要求 ​

  • Windows 下所有 Python 脚本加 -X utf8 参数
  • Bitcointalk HTML 编码：ISO-8859-1
  • 输出编码：UTF-8
  • 构建缓存问题：失败时清空 .temp 和 cache 目录

12. 数据局限性与已知问题 ​

  1. 数据采集偏向 PoW 币种：Bitcointalk ANN 板块历史上以 PoW 挖矿币为主，2017-2021 年的 DeFi/NFT 热潮覆盖不足
  2. 交易所范围有限：仅覆盖 SafeTrade 和 Nonkyc 两家小型交易所，不涵盖 Binance、Coinbase 等主流交易所
  3. 回复/浏览统计滞后：依赖于板块列表页的批量扫描（可增量），非实时
  4. 上币验证依赖人工：exchange_verified.json 需手动整理和更新
  5. 文件名问题：ticker 段可能含中文（如 BGG链），英文名段可能为空（如 奥创AI_ULTAI_.md），需要人工修正
  6. 研究报告限制：仅覆盖 2026 年之后的项目，且需要同时满足交易所上市和验证两个条件
